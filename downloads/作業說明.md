# 作業：Gmail 自動讀寫程式（應用程式密碼認證）

## 作業目標

撰寫一支 Python 程式，使用 Google 帳戶的 **16 字元應用程式密碼** 登入 Gmail，
透過 **IMAP 自動讀取信件**、透過 **SMTP 自動寄送信件**，並實際執行後撰寫報告。

本資料夾提供 `gmail_auto.py` 作為範例，同學可以直接執行、修改或參考其寫法自行重寫。

## 前置準備

1. 準備一個 Gmail 帳號（建議用測試用帳號，不要用個人主要帳號）。
2. Google 帳戶 → 安全性 → 開啟「兩步驟驗證」。
3. 在搜尋列輸入「應用程式密碼」→ 建立 → 取得 16 字元密碼（例如 `abcd efgh ijkl mnop`）。
4. 複製 `config.example.json` 為 `config.json`，填入帳號與應用程式密碼。
   **config.json 不可繳交、不可上傳、不可貼在報告中。**
5. 執行測試：

```
python gmail_auto.py selftest
python gmail_auto.py read --limit 5
python gmail_auto.py send --to 同學@gmail.com --subject "測試" --body "你好"
```

每次執行都會在 `results/` 目錄留下 `run_日期時間.md` 與 `.json`，裡面是這次執行的真實結果，寫報告時直接引用。

## 程式功能要求

| 編號 | 要求 | 必要 / 加分 |
|---|---|---|
| F1 | 以應用程式密碼登入 IMAP（imap.gmail.com:993）並讀取收件匣最新 N 封信，印出日期、寄件者、主旨 | 必要 |
| F2 | 以應用程式密碼登入 SMTP（smtp.gmail.com:465）寄出一封信給指定收件者 | 必要 |
| F3 | 寄信後再讀信，驗證寄出的信確實收到 | 必要 |
| F4 | 帳號密碼不得寫死在程式碼中，須由設定檔或環境變數讀取 | 必要 |
| F5 | 登入失敗、網路錯誤時要有清楚的錯誤訊息，程式不可直接崩潰 | 必要 |
| F6 | 只讀未讀信 / 指定日期之後 / 指定主旨關鍵字等篩選條件 | 加分 |
| F7 | 寄送附件、自動回覆、或將信件存成檔案等延伸功能 | 加分 |

## 報告要求

報告使用 Word、PDF 或 Markdown 皆可，**必須包含以下三部分**，缺一項即扣分。

### 1. 報告題目

自訂一個能表達本次作業內容的題目，例如：
「以應用程式密碼實作 Gmail 自動收發信程式」。
不可直接寫「作業一」或「Gmail 報告」。

### 2. 目的

說明這支程式要解決什麼問題、為什麼要用應用程式密碼而不是一般登入密碼，以及預期達成的效果。
建議 100 到 200 字。

### 3. 報告內容項目（**全部必須依實際執行結果撰寫**）

以下每一項都要有自己實際跑出來的證據（執行畫面截圖，或 `results/` 紀錄檔內容）。
抄範例、憑想像寫的結果一律不計分。

| 項目 | 必須包含的內容 |
|---|---|
| 3.1 執行環境 | 作業系統、Python 版本、使用的套件、測試用 Gmail 帳號（可部分遮蔽，如 abc***@gmail.com） |
| 3.2 認證設定過程 | 開啟兩步驟驗證與建立應用程式密碼的步驤截圖，**密碼本身必須遮蔽** |
| 3.3 程式架構說明 | 程式分成哪幾個部分、各部分做什麼、用到哪些函式庫（imaplib、smtplib、email 等） |
| 3.4 讀信結果 | 實際讀到的信件清單截圖或表格（日期、寄件者、主旨），並說明信箱總數與讀取筆數 |
| 3.5 寄信結果 | 寄出的收件者、主旨、時間，並附上收件端實際收到的截圖 |
| 3.6 寄送後驗證 | 寄出後再讀信，是否有讀到剛寄的那封，花了多久 |
| 3.7 錯誤與排除 | 過程中實際遇到的錯誤（例如 535 認證失敗、IMAP 未啟用、連線逾時）、原因與解法。若完全沒遇到錯誤，請故意輸錯密碼測一次並記錄程式的反應 |
| 3.8 結論與心得 | 程式是否達成目的、哪裡可以改進、學到什麼 |
